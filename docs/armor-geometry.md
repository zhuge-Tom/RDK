# 红蓝灯条几何优化

2026-11-07。在电脑源码和RDK独立模块完成修改后，用户反馈现场初测可用并要求发布至main。运行仍是RDK海康MVS → C++ ROS 2 → 电脑浏览器。

## 修改及原因

旧实现按轴对齐包围框的宽高和灯条中心的画面横纵差过滤。目标在画面内转动时，包围框变宽、两中心纵差变大，即使灯条本身仍细长且平行，也可能被排除。近距离时LED之间的间隙投影变大，固定15px闭运算可能不能连成整根灯条。侧向转动时灯条中心距缩短，旧配对宽高门槛也可能拒绝。

现在改为：

- 使用旋转框长短边及方向判断灯条，在两灯条的平均方向坐标系中判断中心连线。
- 基础闭运算后，按宽度、方向、共线关系合并LED片段；跨片段间隙上限取15px和3倍平均宽度的较大值。合并后重检形状，面积只累计真实轮廓面积。
- 同时约束两灯条夹角、相对错位、长度比、间距比和凸四角形；拒绝触边截断灯条，避免用残缺长度解算PnP。
- 候选片段最多128个，按面积保留，限制组合处理量。
- 检测计数经ROS消息传到HTTP和浏览器调试区；断流清空。剔除项是候选计数，不能单凭某一计数认定目标本身为何漏检。

配置在`config/blue_vision_ros.yaml`。共用最小面积45、长边16px、短边3px、长短边比1.8；灯条距竖直方向上限75°、两灯条方向差20°、连线偏离法向25°。这些是过滤参数，**不是实拍最大可识别角度承诺**。红蓝分割阈值、曝光3500us、增益2、30FPS未调整。

## 现场复测方法

先红色：固定镜头环，约1.5–2m正对、完整入画并静止2秒；再分别慢慢做画面内倾斜、向左/右侧转，每个姿态停2秒；最后正对缓慢靠近，保持两根灯条全部在画面内。第一次漏检时保持姿态并告诉助手，以便抓原图和诊断。随后切蓝色重复。无需先精确测量角度。

近到画面截断、严重失焦/过曝、接近侧面看不到完整灯条时仍可能无法检测。需结合原始帧判断，不能无限放宽门槛。不要为了近处重新转对焦环而混用标定。

K/D、W130mm/H59mm及验证标志不变：`calibration_verified=0`、`distance_validation_verified=0`，仍为显式未核验PnP调试。镜头未变无需因算法优化重拍棋盘；新姿态角点与测距仍须实际核对。蓝色历史静态测距记录保持原样。
